# CompHub V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** Turn CompHub into a Luarkampus-style catalog with public organizer submissions, admin moderation, separate registration status, and safe archive behavior while preserving all four real events.

**Architecture:** Native PHP 8.5 MVC plus PostgreSQL. Schema changes are ADD-only: new nullable columns, new topic rows, deactivated legacy categories, and no deletes or NOT NULL changes. Public submissions use the internal verified `Tim Kurasi CompHub` provider as technical owner while storing real organizer verification fields on the event. Moderation uses `events.status`; registration state is computed from `registration_start_at` and `registration_deadline`. Revision is the existing `changes_requested` state labelled “Perlu revisi”.

**Tech Stack:** PHP 8.5, PostgreSQL, custom MVC, PHP built-in server, file-based tests.

**Spec:** User-approved final refinement in the execution conversation. No separate spec file exists.

## Global Constraints

- Preserve exactly 4 real events and `Tim Kurasi CompHub`; never seed dummy events/users.
- No `DROP TABLE`, `DROP COLUMN`, `DELETE` of legacy data, or NOT NULL changes.
- Login `next` accepts only local single-slash paths and preserves query strings.
- Provider role cannot log in; admin default destination `/admin`, user `/dasbor`.
- Public visibility: `status='approved'`, active topic, `archived_at IS NULL`.
- Archive never deletes bookmarks or moderation logs.
- New public submissions require poster; competitions require PDF guidebook. Legacy events are exempt.
- Poster max 2 MB (JPEG/PNG/WebP); guidebook max 5 MB PDF; stored outside webroot.
- Revision token: 256-bit secret, SHA-256 hash only, 14-day expiry, revocable, rate-limited, no-referrer/no-store.
- Visual shell: white navbar, pale blue filter sidebar, month tabs, 3-column desktop cards, consistent poster area, deadline and bookmark.
- Existing server command remains `cd public && php -S localhost:8000`.

## Review Focus

- `next` values that decode into protocol-relative or backslash paths.
- Archived events leaking into catalog, saved page, media, or bookmark mutations.
- Legacy events losing public visibility during category remap.
- Revision token leaking via referrer, cache, logs, or non-constant-time compare.
- Public submission bypassing required organizer verification fields or file constraints.
